User Account Access Reset — Internal Procedure
Version 2.1  |  Last updated: some time ago  |  Owner: IT Operations
Purpose

This document describes the process for resetting a user account when access has been lost or locked. It applies to all standard employee accounts across the company's internal systems.
Who Should Use This

This procedure is for IT support staff and team leads. Anyone else who needs to reset an account should contact the help desk.
Before You Start

Make sure you have the right permissions. Also, the system should be in a stable state before proceeding. If there are any issues, resolve them first.
Steps to Reset an Account
  1. Go to the admin panel.
  2. Find the user. Search by name or ID.
  3. Select the account and choose Reset Access.
  4. The system will process the request. Wait for it to finish.
  5. Notify the user that their access has been reset.
  6. Document everything in the usual place.
What to Do If It Doesn't Work

If the reset fails, an error message will appear. Try the process again. If the issue continues, escalate it to the appropriate team. Make sure to include the relevant information when you escalate.
After the Reset

After the reset is complete:

  • Confirm the user can log in successfully before closing the ticket.
  • If the reset was triggered by a suspected security issue, notify your security team immediately and keep the ticket open pending their review.
  • Update the ticket with the date, time, and your name.
⚠ Note: Do not share temporary credentials over email. Use the secure messaging system.
Security Notes

Resets should only happen after verifying the identity of the requester. Verification can be done in various ways. Use your judgment. Unauthorized resets are a security risk and should be treated seriously.

User Account Access Reset — Internal Procedure
Version 2.2  |  Last updated: Today  |  Owner: IT Operations  |  Reviewed by: You
Purpose

This document describes the process for resetting a user account when access has been lost or locked. It applies to all standard employee accounts across the company's internal systems.

Who Should Use This

This procedure is for IT support staff and team leads. Anyone else who needs to reset an account should contact the help desk.

Before You Start

Before starting, confirm you have IT Admin access in the user management portal. Check that the account management system is online (green status on the IT dashboard) and that no maintenance window is currently active. If either condition is not met, stop and contact the IT Operations team before continuing. Make sure you have the right permissions. Also, the system should be in a stable state before proceeding. If there are any issues, resolve them first.

Steps to Reset an Account
  1. Go to the admin panel.
  2. Find the user. Search by name or ID.
  3. Select the account and choose Reset Access.
  4. The system will process the request. Wait for it to finish.
  5. Notify the user that their access has been reset.
  6. Log the completed reset in the IT ticketing system (ServiceDesk → Account Management → Access Resets). Include: the employee name, their account ID, the date and time of the reset, the reason for the reset, and your name. Mark the ticket as Resolved only after confirming the user can log in. Document everything in the usual place.
What to Do If It Doesn't Work

If the reset fails, an error message will appear. Try the process again. If the issue continues, escalate it to the appropriate team. Make sure to include the relevant information when you escalate.

After the Reset

After the reset is complete:

  • Confirm the user can log in successfully before closing the ticket.
  • If the reset was triggered by a suspected security issue, notify your security team immediately and keep the ticket open pending their review.
  • Update the ticket with the date, time, and your name.
⚠ Note: Do not share temporary credentials over email. Use the secure messaging system.
Security Notes

Before resetting any account, verify the requester's identity using two steps: (1) confirm their employee ID number matches the account being reset, and (2) ask them to confirm the email address on file for the account. If you cannot verify both, do not proceed — contact your team lead before continuing. Verification can be done in various ways. Use your judgment.

What the three fixes actually changed
1 "Before You Start" — Changed from vague ("have the right permissions") to specific (IT Admin access in the user management portal, green status on the dashboard). Someone new to this process can now actually follow it.
2 "Document everything in the usual place" — Named the exact system (ServiceDesk), the exact path, and the exact fields to fill in. This eliminates the assumption that everyone knows "the usual place."
3 "Use your judgment" — Replaced with a two-step verification process (employee ID + email on file). This is the most critical fix — "use your judgment" on a security step is a gap that creates real risk.

What This Activity Showed

✓

Good documentation isn't all-or-nothing. Even a weak document usually has parts that work — spotting those is just as useful as spotting the problems.

✓

Vague language is the most common documentation problem. Words like "the usual place," "use your judgment," and "the right permissions" might make sense to the person who wrote them — and mean nothing to the person reading them for the first time.

✓

The goal of a review isn't to find flaws — it's to make the document usable by someone who wasn't in the room when it was written. Specific beats general every time.
